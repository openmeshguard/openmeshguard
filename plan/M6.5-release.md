# M6.5 — v0 Release Engineering

Branch: `m6.5-release`

## Goal
Cut `v0.1.0` once M6c lands: reproducible signed release artifacts, an install path beyond `go install`, and the first-impression docs a public download deserves. No product behavior changes.

## Context
Triggered by M6c completion (the DoD "first-run zero-config scan produces the SPEC §6-shaped summary with honest unknowns" is the release criterion). The `go install` path and ldflags version stamping already exist (PR #6); this milestone adds the binary-distribution tier.

## Deliverables
- [x] goreleaser config: darwin/linux × amd64/arm64 archives, `-ldflags "-X main.version="` wired to the tag, checksums file. Reuse the existing `VERSION=` make override.
- [x] Release workflow (tag-triggered) building and publishing GitHub Release artifacts; cosign signing of archives + checksums.
- [x] Verify the e2e goldens that pin `scanner.version: "dev"` are unaffected by release builds (release stamps a real version; `make build` still yields `dev`) — or scrub the field. Confirm before tagging.
- [x] README: promote the alpha `go install` line to a real install section (release binaries + `go install`), accurate quickstart matching shipped commands, honest "what works / what's next" table.
- [x] SECURITY.md (disclosure policy — this is a security tool), CHANGELOG.md for v0.1.0, and a short release note framing v0 as declared+resolved posture with runtime verification (M7) as the headline still to come.
- [x] Optional: Homebrew tap formula, since the audience is platform/security engineers who won't all have a Go toolchain. Completed as a separately reviewed follow-up after the initial v0.1.0 release.

## Definition of Done
- [x] `v0.1.0` tagged; release artifacts built, signed, checksummed, and downloadable; a downloaded binary runs `openmeshguard version` reporting the tag and completes a scan.
- [x] README install path verified from a clean machine (both `go install @v0.1.0` and a release binary).
- [x] No product/scan behavior changed vs. M6c; `make build test lint schema-test` + e2e green.

## Out of scope
Any scanner feature work, M7 runtime verification.

## Deferred
- Homebrew distribution was deferred at initial v0.1.0 publication; that deferral is superseded by the completed follow-up recorded below.
- M7 remains the next product milestone; do not delay v0 for telemetry implementation.


## Summary

### Architecture and progress assessment

M0–M6c are implemented and M6c merged before this release branch. The architecture
remains typed, bounded collection → normalization → pure mTLS/authorization
resolver → YAML/CEL and governance → canonical JSON → HTML/SARIF/score/CI
projections. Current resolver semantics are `mtls/v5,authz/v8`; the frozen
contracts, scanner behavior, RBAC, control packs, and golden fixtures are unchanged
by M6.5. M6c was freshly verified with build/unit/lint/schema checks, a 62-second
Kind acceptance run, all fixture goldens, and 456 approved list-only scanner audit
events before handoff.

The milestone plan establishes v0 after M6c, with M6.5 cutting `v0.1.0` and M7
adding runtime verification. The earlier SPEC's runtime MVP language does not
change that higher-precedence release sequence. v0 documentation explicitly
states declared/resolved posture and unavailable runtime verification.

M6.5 is complete: the reviewed release branch merged, `v0.1.0` was tagged, and
the signed release was published after downloaded-binary and clean-install
verification. M7 is the remaining post-v0 product milestone and supplies Prometheus auth, bounded/chunked queries and fallback, verified
postures and runtime controls, fake-server tests, and a traffic-backed demo.
Existing deferred contract extensions and optional UI redesign stay outside this
release.

### Release decisions

- Pin GoReleaser v2.18.2, Cosign v3.1.3, and GitHub Actions to verified commits.
- Four tar.gz archives receive individual Sigstore bundles; checksums.txt receives
  its own bundle. Verification constrains the exact tag workflow identity and
  GitHub OIDC issuer before accepting bytes.
- Create a draft, download its artifacts afresh, verify signatures/checksums and
  the native binary version, then test clean tagged Go installation, live Kind
  scanning/schema validation, and default-dev acceptance before publication.
- Runtime smoke runs on the workflow's native Linux amd64 host, with a separate
  orchestrator macOS arm64 downloaded-binary scan. The other targets are built
  and their signatures/checksums verified; this does not claim all four were executed.
- Private vulnerability reporting was enabled and verified by the orchestrator
  before SECURITY.md linked GitHub's private reporting form.

### Homebrew follow-up completion — 2026-09-29

- Public tap: [openmeshguard/homebrew-tap](https://github.com/openmeshguard/homebrew-tap).
  Install with `brew install openmeshguard/tap/openmeshguard`. The formula
  supports the existing macOS/Linux arm64/amd64 release archives and requires
  no Go toolchain. No scanner code, RBAC, or frozen contracts changed.
- The formula pins each archive SHA-256. Homebrew verifies those checksums during
  installation; it does not verify Sigstore signatures. Before generation, the
  maintainer generator verifies the signed checksum file and all four signed
  archives against the exact tag release workflow identity and GitHub OIDC issuer.
  This is not an Apple Developer ID signature or notarization claim.
- Tap update automation accepts an already public stable release tag, verifies its
  artifacts, then pushes a review branch and writes a comparison / pull-request
  creation URL to the job summary. A maintainer opens and reviews the PR before
  merging. The organization does not permit Actions to create or approve PRs;
  the workflow respects that policy, uses only repository-scoped contents-write
  access, and needs no cross-repository PAT.
- Independent reviews completed before publication. The local installation was
  then tested from the actual public tap: `brew install`, `brew test`, and
  `brew audit --strict` passed on macOS arm64. The installed binary executed
  `version` and reported `version=v0.1.0`; its SHA-256 matched the independently
  verified release binary:
  `c0139f2ddfc9ba9d7f244750126f76fb142c52a836dd61bbddc465f81ce5e9a0`.
- All four archive signatures/checksums were verified before formula generation.
  Native Homebrew installation/execution was verified only on macOS arm64;
  macOS amd64 and Linux arm64/amd64 formulas were prepared and their artifacts
  verified, but those platforms were not natively installed or executed here.
- This closes the optional Homebrew distribution deliverable for v0.1.0.
  Later release updates must first pass the same signed public-release checks;
  this record makes no claim that v0.2.0 has been published or installed.
